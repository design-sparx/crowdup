# AGENTS.md

CrowdUp: an open-source, self-hostable donation crowdfunding app (React Router 8 framework mode with server rendering, React 19, TypeScript 6, Tailwind 4, shadcn/ui on Base UI, Vite 8) backed by Supabase (Postgres, Auth, Storage) and Stripe Connect. Deployed on Netlify. Operator docs are in `docs/` (start at `docs/README.md`).

## Commands

pnpm is the package manager (`pnpm-lock.yaml`). Use `pnpm`, not `npm` or `yarn`.

- `pnpm dev` starts `react-router dev` (default http://localhost:5173)
- `pnpm build` runs `react-router typegen`, `tsc`, then `react-router build` (output in `build/client`; type errors fail the build)
- `pnpm lint` runs ESLint with `--max-warnings 0`, so any warning fails
- `pnpm preview` serves the static `build/client` only (no SSR); to run the real server use `pnpm exec react-router-serve build/server/index.js`
- `pnpm test` runs Vitest unit tests (`src/**` and `scripts/**`; `e2e/` is excluded)
- `pnpm test:db` runs `supabase db reset` then `supabase test db` (pgTAP in `supabase/tests/database/`; needs Docker and the Supabase CLI)
- `pnpm test:e2e` runs Playwright (`e2e/`) against the production build on port 4173; run `pnpm build` first and have local Supabase running

## Conventions for the rebuilt UI

These apply to all UI code (Tailwind + shadcn on Base UI). The UI rebuild is finished; the Architecture notes below describe the current structure.

- **File and folder names are kebab-case**: `donate-panel/donate-panel.tsx`, `use-donation-form.ts`. The exported component is still PascalCase (`DonatePanel`). Reason: Windows and macOS ignore case but Linux CI does not, so case-only differences break builds.
- **Exceptions that keep their current names:** `src/components/ui/` (generated by the shadcn CLI, kebab-case, do not hand-edit), `src/lib/` and `src/data-access/` (camelCase, with the `.server.ts` suffix for server-only modules), and route modules in `src/routes/` (kebab-case).
- **One folder per component**, holding `name.tsx`, `name.test.tsx`, an optional `name.stories.tsx` (stories are optional for now; do not create empty ones) and a one-line `index.ts` that re-exports only that component: `export {DonatePanel} from "./donate-panel"`.
- **No aggregate barrels.** Do not add `index.ts` files that re-export many modules (such as `features/donate/index.ts` or `components/index.ts`); they slow dev builds and cause circular imports. Import the component folder directly: `@/features/donate/donate-panel`.
- **Organise UI by journey, not by layer.** `src/features/<journey>/` (`donate`, `organiser`, `admin`, `auth`, `content`) holds that journey's screens and components. Shared shell pieces live in `src/components/shell/`. Move a component to a shared folder only when a second feature needs it. Route modules stay thin and import the screen from its feature folder.
- **Server code is not feature code.** Loaders, actions, `src/data-access/**` and `src/lib/**` keep their current structure and tests.
- **Every component has a test** (`name.test.tsx`, Vitest with Testing Library).
- Use `@/` imports for anything outside the current folder, Tabler icons only (`@tabler/icons-react`), and `cn()` from `@/lib/utils` to join class names.
- Load heavy client-only code (the Tiptap editor, charts) only on the screens that use it, with dynamic imports.

## Architecture

- `react-router.config.ts` sets `appDirectory: "src"` and `ssr: true`. `src/root.tsx` is the root: the HTML shell, `globals.css`, the theme init script (`src/lib/theme.ts`), the shadcn `Toaster` and the demo banner.
- `src/routes.ts` is the route config. Each entry points at a thin route module in `src/routes/`. Route modules keep the loader, action, `meta` and `ErrorBoundary`, and render a screen from `src/features/<journey>/`. Layout routes: `site-layout` (public site and sign-in), `dashboard-layout` (organiser, signed in), `admin-layout` (admin inbox, which 404s non-admins).
- Screens live in `src/features/<journey>/` (`donate`, `organiser`, `admin`, `auth`, `content`). One folder per component with `name.tsx`, `name.test.tsx` and a one-line `index.ts`. There are no aggregate barrels. Shared shell pieces (header, footer, theme toggle, error page) are in `src/components/shell/`, and shadcn primitives in `src/components/ui/` (generated; do not hand-edit).
- Netlify deploys via `@netlify/vite-plugin-react-router` (generates the SSR handler; `netlify.toml` needs no redirects). Unknown paths render server-side with a real 404. Routes export `meta` built with `buildMeta` from `src/helpers`. Browser-only code (window, Tiptap `useEditor`) must be guarded: use effects or `immediatelyRender: false`. Run the production build locally with `react-router-serve build/server/index.js`.
- Data and server code: `supabase/migrations/` is the schema (RLS, security-definer functions, storage bucket); `supabase/seed.sql` is local sample data and `supabase/demo-seed.sql` is demo only. `src/data-access/<area>/` (auth, campaigns, donations, moderation, reports, stripe, payments) holds `*.server.ts` modules wiring Supabase and Stripe to loaders and actions, plus unit-tested helpers beside them. `src/lib/<area>/` holds pure, unit-tested logic (status transitions in `src/lib/campaigns/transitions.ts` mirror the SQL). Stripe webhook: `src/routes/api-stripe-webhook.tsx`.
- Configuration is server-side environment variables only (read via `process.env`, no `VITE_` vars). The full list is in `docs/self-hosting.md` and `.env.example`; add new variables to both and to `netlify.toml` `[template.environment]` if required.
- `src/types/index.ts` holds shared types. `src/data/*.json` still provides static countries, currencies, footer links, testimonials and a mock user; campaigns come from Supabase. Legal page text is configured in `src/data/legal.ts` (operator placeholders, see `docs/operators-legal.md`).
- `scripts/` holds the demo reset (guarded, unit tested; app-side demo logic is in `src/lib/demo`). Tests: Vitest beside the code, pgTAP in `supabase/tests/database/`, Playwright specs in `e2e/`. CI is in `.github/workflows/` (CI, database permissions, end-to-end, demo reset, release-please); commits follow Conventional Commits.
- Charts use `recharts` through the shadcn `chart` component. The rich text editor uses `@tiptap/react` with the shared extension list in `src/lib/campaigns/storyExtensions.ts`; server-only story rendering lives in `src/lib/campaigns/story.ts`, which the browser bundle must not import.
